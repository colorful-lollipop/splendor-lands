# 璀璨宝石 · 微信小程序

把线上的 H5 牌桌封装成普通微信小程序：**小程序原生封面页 + `web-view` 牌桌 + 横屏锁定**。

线上地址：<https://splendor.zulogic.cn>

## 重要：合规边界

> **本目录是技术演示 / 非个人主体内部验证用的 `web-view` 外壳，不是推荐的公开发布方案。**

微信官方规则明确：

- `web-view` **不支持个人类型小程序**，也**不支持小游戏**。
- 小程序内嵌网页的服务内容，必须与小程序选择的类目一致；不得通过内嵌网页绕开平台规则（《微信小程序平台运营规范》类目不符、绕开审核相关条款）。
- 本游戏是完整游戏内容。用“工具 / 娱乐”等非游戏类目承载它，属于**类目不符 / 规避审核**，可能被拒审、要求整改、限制功能直至下架。
- 换成个体工商户或企业主体，也不会让“非游戏类目 + web-view 套游戏”变成合规；主体升级只解决“能不能用 web-view”，不解决“内容是不是游戏”。

如果目标是**公开上架、长期运营**，请走原生小游戏 + 游戏类目 + 对应资质，或者保留 H5 网站分享。`web-view` 外壳适合内部演示、快速验证和小范围测试，不适合作为正式发行方案。

## 个人主体可以走什么

| 路线 | 能否用 web-view | 是否需要版号 | 说明 |
| --- | --- | --- | --- |
| 个人主体普通小程序 | 否 | 不适用 | 只能做非游戏服务；做游戏属于类目不符 |
| 个人主体小游戏（免费、无内购 IAA） | 否 | 平台现行通道可不提交版号 | 需软著、自审、备案；不能选文化互动 / 角色类 / 牌类；法规层面仍有争议，以后台实时要求为准 |
| 个体工商户 / 企业小游戏（免费 IAA） | 否 | 平台 IAA 通道通常不要求版号 | 类目更完整，仍需软著、自审、备案 |
| 个体工商户 / 企业小游戏（内购 IAP） | 否 | 必须版号 | 需网络游戏出版物号核发单等资质 |
| H5 网页（现状） | — | 不经过小程序审核 | 微信内可直接分享链接；但游戏内容仍受外部链接规范与相关法规约束 |

个人主体如果要做这个小游戏，现实路径是**原生小游戏重写**（Cocos / Laya / PixiJS 等 Canvas 方案），不能直接复用当前 React DOM 页面，也不能用 `web-view`。

## 业务域名

如果只是非个人主体内部验证 `web-view`，仍需：

- 业务域名完成 **ICP 备案**、使用 HTTPS；
- 在小程序后台配置 `web-view` 业务域名并上传校验文件。

## 目录

```
miniprogram/
├─ app.js / app.json / app.wxss
├─ config.js                 # 线上游戏地址与分享标题

│  ├─ cover.jpg              # 首页封面
│  └─ share.jpg              # 分享卡片
└─ pages/
   ├─ index/                 # 原生封面页，竖屏
   └─ game/                  # web-view 牌桌，强制横屏
```

## 已实现

- 原生首页：封面、玩法标签、进入牌桌按钮。
- 进入牌桌后 `pageOrientation: "landscape"` 强制横屏，贴合 H5 的手机横屏布局。
- `web-view` 加载线上游戏，包含联机、房间、断线重连、皮肤、图鉴等全部 H5 功能。
- 加载提示与失败重试弹窗。
- 分享给好友 / 朋友圈：分享卡片使用本地 `assets/share.jpg`。
- 分享路径支持带房间号：`/pages/index/index?room=ABCD`，打开后直接进入该房间的牌桌。
- 小程序更新提示。

## 前置条件

1. 一个**非个人主体**的小程序 AppID（企业、个体工商户或其他组织）。
2. 已备案并可 HTTPS 访问的域名。当前 `splendor.zulogic.cn` 已满足；换域名时同时修改 `config.js`。
3. 微信开发者工具（稳定版即可，基础库 ≥ 2.5.0）。

## 配置步骤

### 1. 导入项目

微信开发者工具 → 导入项目 → 目录选择本仓库的 `miniprogram/`。

把 `project.config.json` 里的 `appid` 换成自己的 AppID：

```json
{
  "appid": "wx1234567890abcdef"
}
```

### 2. 配置业务域名

小程序后台 → **开发管理 → 开发设置 → 业务域名** → 添加：

```
splendor.zulogic.cn
```

微信会给出一个校验文件（例如 `MP_verify_xxxxxxxx.txt`）和文件内容。把它放到网站根目录：

```bash
# 在项目根目录创建，文件名和内容以微信后台为准
public/MP_verify_xxxxxxxx.txt

# 重新构建并部署
npm run build
```

部署后确认下面这个地址能直接打开，再回后台点击校验：

```
https://splendor.zulogic.cn/MP_verify_xxxxxxxx.txt
```

> 校验文件放在 `public/` 根目录，Vite 构建时会原样复制到 `dist/`，Express 会直接提供。

### 3. 本地预览

开发者工具 → 详情 → 本地设置 → 勾选 **“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”**。

编译后即可在模拟器看到封面页；点击“进入牌桌”会加载线上 H5。

> 该勾选只对开发者工具有效。真机体验版/正式版必须完成第 2 步的业务域名配置。

### 4. 真机预览（内部验证）

1. 开发者工具点击“预览”，用手机扫码；确认横屏、联机、音效正常。
2. 把版本设为“体验版”，仅邀请内部成员测试。

**不要**用“工具 / 娱乐”等非游戏类目把这个版本提交公开审核。它只能作为内部演示；公开上架需要原生小游戏 + 游戏类目 + 对应资质。

## 正式上架建议

- 如果必须上微信公开运营：把渲染层重写为小游戏 Canvas（Cocos / Laya / PixiJS 等），选择“游戏”类目。
- 免费、无内购：按 IAA 小游戏流程准备软著、自审、备案；是否可免版号以后台实时要求为准。
- 有内购：必须版号，并准备网络游戏出版物号核发单等材料。
- 个人主体：不能选文化互动 / 角色类 / 牌类；如果本游戏被归入牌类，个人主体无法上架。
- 小程序名称、简介、截图避免使用“官方”“正版授权”等字样；本项目是非官方粉丝作品。

## 联机说明

- 小程序里的 `web-view` 与浏览器打开的是同一个线上服务，玩家可以互通。
- 房间号、邀请链接仍由 H5 内部生成；小程序分享卡片目前分享的是首页或带房间号的启动页。
- 从 H5 复制出来的邀请链接是 `https://splendor.zulogic.cn/?room=XXXX`，在微信里可直接用浏览器打开；小程序内也可以手动输入房间号加入。
- 房间状态保存在服务器内存中，服务重启会清空。

## 常见问题

**打开 web-view 提示“不支持打开非业务域名”**

业务域名未配置成功，或使用了子域名但未在后台配置。确认 HTTPS、ICP 备案、校验文件都能访问，并在真机上重试。

**开发者工具能打开，真机打不开**

开发者工具的“不校验合法域名”只影响工具；真机必须配置业务域名。

**一直是竖屏**

确认 `pages/game/game.json` 里的 `"pageOrientation": "landscape"` 没有被改掉，且基础库版本 ≥ 2.5.0。

**个人小程序可以用吗**

不能。`web-view` 不对个人类型小程序开放，需要企业、个体工商户或其他组织主体。

## 自检

```bash
node scripts/miniprogram-check.mjs
```

会检查页面文件是否齐全、JSON 是否合法、牌桌页是否锁定横屏、包体是否小于 2MB、封面尺寸是否正确，并请求一次线上 `/api/health`。
